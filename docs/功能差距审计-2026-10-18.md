# OfficeBox 功能差距审计（2026-10-18）

这是功能补齐前的历史快照，后续实现见《非OCR功能对齐-2026-10-18》《OCR内置说明》和《Qwen备用OCR》。`reference/OfficeBox/` 表示审计时使用的原版离线包内部路径；原版文件不随本仓库提供。本记录已移除本机个人目录前缀。

本次为功能范围审计，不是转换准确率或性能评测。当前 71 个工具条目中，存在有入口不能用、输出类型与工具名称不一致，以及仅完成基础替代流程的情况，不能认为已达到原版功能完整度。

## 证据与边界

- 已查看用户截图和原版主界面（界面版本 3.0.6）。

- 读取并核对离线包帮助文档全部 12 页，渲染查看第 5、6 页。帮助文档版本为 3.0.0、日期 2018-01-11，其宣传范围不自动等于该离线组件均能正常运行。

- 读取给定离线目录中 55 个工具的语言/控件资源，与当前 catalog、UI、engine 源码对照。资源文本表示原版声明的参数/入口，不证明每个算法的实际效果。资源中存在一些复制遗留文字，按上下文筛选，不按单条文案推断转换能力。

- 原版纠偏组件本次未取得可操作的独立窗口；其设置项依据随包 english.lng 的中文控件核对。没有修改原版文件，也未对用户工作文档执行转换。

- 已小范围复现：PDF417 在当前依赖下直接报不支持；计算器输入 50% 会触发 SyntaxError。

- 严重：核心能力缺失、当前不能运行或名实不符；较大：高级参数/交互/批量流程显著不足；一般：基础能力存在但配置与流程较少；待实测：无法据现有证据判定与原版的完整差距。待实测不等于已实现等效。

分类统计：严重 17 项；较大 31 项；一般 10 项；待实测 13 项。这些是本次审计标签，不是完成度百分比。

## PDF 纠偏：已确认的具体差距

| 能力 | 原版离线资源/截图 | 当前实现 |
| --- | --- | --- |
| 输入 | 多 PDF/TIFF，添加目录、包含子目录、文件筛选 | 单个 PDF |
| 加密文件 | 列表密码、输入密码操作 | 没有密码字段，渲染调用也没有传递密码 |
| 角度/算法 | 可调角度范围、倾斜文字（10°内）、中线纠偏 | 固定搜索 -6° 到 +6°，步长 0.2°，投影评分 |
| 处理范围 | 起止页、图片宽高过滤、跳过不支持图片 | 全部页面，没有过滤 |
| 图像设置 | JPEG 质量、裁切页面 | 仅 DPI；没有质量/裁边控制 |
| 输出管理 | 执行/另存、修改信息、原文件备份及备份目录 | 只写固定应用输出目录的新 PDF；不会直接改写输入文件 |
| 任务流程 | 批量列表、进度/取消相关控件 | 主线程同步执行，没有逐页进度/取消 |
| PDF 对象 | 原版对象保留策略未做同样样本验证 | 当前每页必经图像重建，确定会失去原有文字层、矢量和交互对象 |

纠偏并非只差几个按钮：目前 PDF 会整页光栅化，算法搜索范围和输入范围也固定。补齐时应先确定扫描件/文字型 PDF 的处理策略，然后补批量、页范围、角度与过滤设置，再加入进度、取消和前后效果验证。

原版证据：[Deskew 参数资源](<reference/OfficeBox/data/resources/officebox/Deskew/english.lng:15>)。当前证据：[deskew](<../officertools/engine/pdf.py:560>)、[deskew_image](<../officertools/engine/raster.py:54>)。

## 原版存在入口、当前没有独立等效功能

- PDFLinker：给 PDF 批量添加链接及位置/样式设置。原版目录和语言资源均存在，当前 catalog 无对应工具。

- PDFWMRemover：选择样板图片水印后移除。原版资源中有选择图片水印及样板列表；当前只有加水印，没有去水印工具。不能因此推定原版能去除任意类型水印。

- PDFPageCutter：用水平/垂直分割线把单张 PDF 页面切成多页。当前 PDF 分割是拆文档页，不是切一张页面。

- PDFPageMaster 的页面管理：拖拽重排、插入空白页、撤销。当前独立的删除/旋转/提取不能替代完整的页面编辑流程。

- 扫描 PDF 综合优化：原版 PDFOptimizer 声明组合纠偏、黑白、图像重采样和去空白页；当前的 PDF 压缩没有这套组合处理。

- PDF 转 SWF：离线目录中有 pdftoswf，当前无对应工具；是否值得补齐应按实际使用需要决定。

- PDF 转 Excel/PPT、更多第三方组件、在线模板与导航：帮助文档有提及，但该离线包是否完整包含且可运行未核实，不计入已确认缺失工具数。

## 跨工具的共性差距

1. 任务队列：当前多选文件基本是路径字符串，缺可排序列表、逐文件状态、失败项重试。很多原版转换器有批量/监控目录/命令行三种模式；当前虽然有 CLI，但没有目录监控。

2. 响应与控制：UI execute 在主线程调用 run；耗时操作会阻塞窗口，缺进度、取消和暂停。独立原生启动器只减少打包重复，不会补上业务功能。

3. 输出控制：固定应用输出目录，没有统一的自选输出目录、重名策略及格式/质量配置。原版存在覆盖、另存、备份和命名相关控件。

4. 原始信息保留：PDF 纠偏、灰度转换会整页光栅化；Word/HTML/CHM 路径经文本重建，和保留图文结构的转换是不同能力。准确率/版式还原程度需同样样本测量。

5. 离线可用性：已内置的 PDF 渲染和 FFmpeg 不等于所有工具离线可用。OCR 的引擎与语言包、办公文档转换组件仍未内置。

## 建议补齐顺序

1. 先处理名实不符/不能用：PDF417、PDF 阅读、真正黑白二值化、截图标注的形状/文字、屏幕拾色。

2. 以 PDF 纠偏为首个完整工作流：批量 PDF/TIFF、目录导入、密码、页范围、角度/质量/过滤参数、异步进度与取消，并用文字型与扫描型样本验证对象保留和纠偏效果。

3. 建立通用任务队列和输出设置，随后让 PDF 转换、图片处理、压缩、OCR 共用。

4. 再补截图/录屏的区域/窗口/音频与暂停交互，和 OCR 的离线依赖及区域识别。

5. PDF 转 Word/HTML、CHM 版式转换需要单独选择实现路径，不能用“提取文字”作为完成标志。

这份报告仅做审计与优先级整理，本轮未改变业务实现，也未重新生成发布包。
